# ЗСМК MES v1.1 — независимый производственный контур

`mes/` — самостоятельный bounded context MES для оперативного производства на горизонте 1–30 дней. Доменная модель находится в `mes/src/types.ts`, расчётные правила — в `mes/src/core/`, интеграция с PostgreSQL/Supabase — в `mes/src/integration/`, UI — в `mes/src/ui/`.

## Назначение

MES отвечает за производственные заказы и партии, оперативные задания и их жизненный цикл, назначение сотрудников и оборудования, фактический выпуск и брак, простои, ППР/ремонты, ОТК, диспетчеризацию, календарь и операционное перепланирование.

## Архитектурный принцип

PostgreSQL/Supabase является источником истины для авторизованного режима. Производственные мутации выполняются через контролируемые RPC с серверной валидацией, блокировками и optimistic locking. Прямые `INSERT/UPDATE/DELETE` из браузерной роли `authenticated` на контролируемые MES-таблицы закрыты политиками и привилегиями.

Realtime используется как сигнал на повторную загрузку авторитетного снимка, а не как источник частичных локальных мутаций. Календарь защищён ревизией снимка; задания, заказы и критические операции используют проверки актуальной версии/состояния.

Неавторизованный доступ к SECURITY DEFINER MES RPC закрыт на уровне привилегий. Браузерный контур требует authenticated session и серверно разрешённую MES-роль.

## Контроль производства

Жизненный цикл задания включает серверную проверку назначения ресурсов и переходов состояний. Фактический выпуск является append-only фактом. Для заданий с обязательным ОТК достижение планового количества само по себе не завершает задание: одобрение ОТК должно покрывать актуальный объём. Если после частичного одобрения выпущена новая партия, предыдущий approval автоматически теряет покрытие нового объёма и задание возвращается в ожидание ОТК.

Производственный заказ завершаетcя только при выполнении контрольных условий по последней технологической операции, завершении требуемых заданий и обязательном качестве. Синхронизация факта заказа выполняется сервером.

## Тестовый контур

CI запускает полный локальный Supabase reset из миграций, database security regression tests, schema lint, TypeScript/Vitest и production build. В database regression suite входит детерминированный end-to-end lifecycle `production_lifecycle_e2e.sql`, покрывающий назначение, подготовку, optimistic locking, запуск, выпуск партий, Quality Gate и завершение заказа.

## Интеграция

Интеграция с Workforce остаётся отдельным версионированным DTO/API-контуром. Внутренний код Workforce напрямую в MES не импортируется.

## Режим разработки

`npm run dev` запускает Vite, `npm test` — Vitest, `npm run build` — TypeScript + Vite production build. Для локального backend-контра используется Supabase CLI из `mes/supabase/`.
